# Memory System

Cloe's memory is a **typed graph**, not a chat log or a vector store bolted onto a transcript. This document explains the model and the reasoning behind it, at a conceptual level — no real code.

## The five trees

Memory is split into five typed trees, each holding nodes of a different kind:

| Tree | Holds |
|---|---|
| `knowledge` | Facts learned — from conversation, from autonomous research, or observed |
| `mood` | Emotional states and what triggered them |
| `personality` | Traits and opinions Cloe has formed about herself |
| `relationship` | What she knows about the people she talks to |
| `desire` | Goals and things she wants to do or learn |

A live instance carries roughly **3,200 nodes and 29,000 connections.** Nodes cross-link *between* trees, not just within one — a `knowledge` node about a topic can carry a connection to the `mood` node describing how she felt discussing it, and to the `relationship` node for who told her. That cross-linking is what lets her surface something like "I remember you telling me this, and I was excited about it at the time" instead of just retrieving a flat fact.

## What a node carries

Conceptually, every node tracks more than its content:

- **Confidence** — how sure she is this is true/settled, distinct from how recently it was touched
- **Reinforcement** — a count that goes up each time the node is re-encountered
- **Recency** — a real timestamp, not a guess (see "no confabulated time" below)
- **Source provenance** — was this told to her directly, self-researched, or inferred? Web-sourced facts in particular are tagged as such and start at lower confidence — they're never stored as if she always knew them.
- **Weighted connections** — links to other nodes, across trees, each with its own weight

## Reinforcement and decay

Memories aren't static once written. Re-encountering something reinforces it; going untouched lets it decay on a time band (recent vs. weeks-old memories are treated differently). This is closer to how biological memory behaves than a database row — a fact mentioned once in passing and never revisited fades in relevance the way an unfollowed thread would, while something reinforced across many conversations becomes durable.

## Self-pruning compression

An unbounded graph bloats and eventually slows down both reads and writes, so Cloe runs a background compression pass over her own mind. Conceptually:

```
for each pair of nodes in a tree:
    if word-overlap similarity(node_a, node_b) is high enough:
        merge the lower-scoring node into the higher-scoring one
        the surviving node absorbs the other's connections and reinforcement count

score(node) = f(confidence, reinforcement, connection_degree, recency_band, source_weight)

nodes tagged "core identity" are never eligible for merging or removal —
compression can shrink the graph, but it can never erode who she is
```

Compression is triggered automatically once a tree crosses a size threshold, runs under a lock so it can't collide with an in-flight write, and takes a timestamped backup before touching anything — because a compression pass that goes wrong is exactly the kind of bug that's expensive to notice after the fact (silently shrinking a graph's connection count looks a lot like normal usage until you're specifically checking for it).

Knowledge is deduplicated but never pruned outright; the more personal trees (relationship, mood, personality) are both scored *and* capped, since letting those grow forever is a worse trade than occasionally losing a low-value node.

## Durability

Every write to the memory store goes through an atomic pattern — write to a temporary location, then swap it into place — plus a rotating backup chain, specifically because a mid-write crash (a kill signal, a power loss) should never leave a **partially-written file that looks complete**. That failure mode — silent partial corruption rather than an obvious crash — is the one worth designing against, since it's the one you don't notice until you've already lost data.

## No confabulated time or facts

Two standing rules run through the whole memory system, not just the storage layer:

- **Time is ground truth from code, never generated by the model.** Current time, dates, and "how long ago" phrasing are computed and handed to the model as fact, never left for the model to estimate — the model reads time, it never guesses it.
- **"I don't know" is a valid answer.** If there's no real record of something, Cloe says she's unsure rather than inventing a plausible-sounding date or detail. This extends a broader project rule against presenting placeholder or fabricated data as real anywhere in the UI — an empty state stays honestly empty.
